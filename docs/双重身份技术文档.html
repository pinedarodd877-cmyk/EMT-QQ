一、功能概述

本客户端支持在一台计算机上同时连接两个 NapCat 实例（对应两个 QQ 账号），并在不重新登录、不中断会话的前提下，通过点击输入栏的头像按钮即时切换消息发送身份。切换过程为毫秒级，两个账号的消息收发互不干扰。

功能要点：

  • 双账号同时在线，各自独立收发消息；
  • 点击头像按钮即可切换发送身份，附带缩放过渡动画；
  • 仅在两个账号共同所在的群内允许切换身份；
  • 开启"显示昵称"后，自己发出的消息将标注发送账号昵称，便于区分。

二、系统架构

本功能采用"双实例 + 双连接 + 单客户端"架构：

层级组件职责
协议层NapCat 实例 1（账号 A）QQ 登录、消息收发、协议解析，WS 监听 8084 端口
协议层NapCat 实例 2（账号 B）同上，WS 监听 3001 端口
服务层server-proxy.cjs监听 8098 端口，提供 /ws-config 配置分发、图片与 AI 接口代理
客户端qq-client.html建立两条 WebSocket 连接，按当前身份路由发送与渲染

NapCat 本身支持多实例运行：每个账号使用独立的配置目录（config/onebot11_<QQ号>.json），端口各自错开即可共存。因此双账号功能无需修改协议层，全部改动集中于客户端的连接管理与路由逻辑。

需要说明的是：QQ 协议解析由 NapCat 完成，界面框架基于 Stapxs QQ Lite 开源项目，本文档所述的双账号胶水逻辑为本项目自行实现部分。

三、双 WebSocket 连接的建立

连接入口为 dc() 函数。页面加载后读取两个账号的地址与令牌，分别建立 WebSocket 连接，并在各自的 onmessage 回调中携带身份标识（acc）：

function dc() {
  // 账号 A（老号）：WS 8084
  var a = document.getElementById('addr').value.trim();
  var t = document.getElementById('token').value.trim();
  var u = a.startsWith('ws') ? a : 'ws://' + a;
  if (t) u += '?access_token=' + encodeURIComponent(t);
  ws = new WebSocket(u);
  ws.onmessage = function(ev){ hm(JSON.parse(ev.data), 0); };  // acc = 0

  // 账号 B（新号）：WS 3001
  var a2 = document.getElementById('addr2').value.trim();
  var t2 = document.getElementById('token2').value.trim();
  if (a2) {
    var u2 = a2.startsWith('ws') ? a2 : 'ws://' + a2;
    if (t2) u2 += '?access_token=' + encodeURIComponent(t2);
    wsB = new WebSocket(u2);
    wsB.onmessage = function(ev){ hm(JSON.parse(ev.data), 1); };  // acc = 1
  }
}

acc 参数是整套身份体系的核心标识：0 代表账号 A，1 代表账号 B。此后所有响应分发、数据存储、发送路由均以此参数为依据。

四、身份数据的分类存储

所有按账号区分的响应在 ha() 函数中分流存储。核心变量：

变量含义
siA / snA账号 A 的 QQ 号与昵称
siB / snB账号 B 的 QQ 号与昵称
curAcc当前激活的身份（0 或 1）
fr / gr账号 A 的好友列表、群列表（界面主显示）
frB / grB账号 B 的好友、群列表（仅用于共同群判断，不显示）
function ha(r, acc) {
  var d = r.data;
  if (d.user_id && d.nickname !== undefined) {
    if (acc === 1) { siB = d.user_id; snB = d.nickname; }
    else          { siA = d.user_id; snA = d.nickname; }
    if (acc === curAcc) { si = siB; sn = snB; }
    accSyncUi();  // 同步界面头像按钮
    return;
  }
  // 好友/群列表同样按 acc 分存
  if (Array.isArray(d) && d[0].user_id !== undefined) {
    acc === 1 ? (frB = d) : (fr = d);
    rl(); return;
  }
}

五、消息发送的路由机制

所有 API 请求统一经由 sa2() 发送，按 acc 选择对应的 WebSocket：

function sa2(a, p, e, acc) {
  var sock = acc === 1 ? wsB : (wsA || ws);
  if (!sock || sock.readyState !== 1) return;
  sock.send(JSON.stringify({
    action: a, params: p || {}, echo: e || randomEcho()
  }));
}

发送链路：用户在输入栏点击发送 → sm() 组装消息并附带当前身份（acc: curAcc）→ 调用 sa2('send_msg', 参数, echo, curAcc) → 由 sa2 将请求投递至对应账号的 NapCat → NapCat 以该账号身份发出消息。切换身份的本质是更换发送出口，因此无需重新连接或登录。

六、身份切换与界面联动

点击输入栏的头像按钮触发 accSwitch()：

function accSwitch() {
  var na = curAcc === 0 ? 1 : 0;
  // 共同群限制
  if (na === 1 && cc.type === 'g' && !isSharedGroup(cc.id)) {
    toast('该群只有账号1在，无法切换');
    return;
  }
  // 头像缩回动画
  document.querySelectorAll('#dualImg,#dualImg2').forEach(function(im){
    im.style.transition = 'transform 0.15s ease-in';
    im.style.transform = 'scale(0)';
  });
  setTimeout(function(){
    curAcc = na; si = (na === 1 ? siB : siA); sn = (na === 1 ? snB : snA);
    accSyncUi();
    // 新头像弹出动画（回弹曲线）
    // transform: scale(1)，transition: cubic-bezier(0.34,1.56,0.64,1)
  }, 150);
}

界面联动由 accSyncUi() 完成：更新头像按钮的图片地址（ga(siA/siB)）、更新按钮提示文字，并控制 AI 润色按钮与头像按钮的显隐切换（开启双重身份时，AI 按钮隐藏、头像按钮原位显示）。

七、共同群权限控制

为避免在账号 B 不存在的群内使用其身份发送消息，系统限制身份切换仅允许在两个账号的共同群中进行：

function isSharedGroup(gid) {
  return (grB || []).some(function(g){
    return String(g.group_id) === String(gid);
  });
}

grB 为账号 B 的群列表，在连接成功后拉取一次，仅用于交集判断，不参与界面显示。账号 B 不在当前群时，切换请求被拒绝并给出提示。

八、消息去重机制

双账号环境下存在两类消息重复问题，需分别处理。

8.1 群消息双推去重

两个账号同时存在于同一群时，群消息会分别从两个 NapCat 实例推送，且两个实例对同一条消息分配的 message_id 不同，无法按 ID 去重。解决方案是采用内容签名加时间戳的组合键：

// 群消息专用去重
var sig = '';
d.message.forEach(function(m){ sig += m.data.text || '[img]'; });
var key = ci + '_s_' + sig + '_' + d.time;
if (sms[key]) return;  // 第二条推送被丢弃
sms[key] = 1;

同一条群消息在两个实例推送时的文本内容与时间戳完全一致，因此第二条必然命中去重。

8.2 自发消息回显去重

自己发送消息后，NapCat 会将消息回推。客户端在发送瞬间已插入"乐观气泡"（本地立即显示），若回显再次插入将产生重复。处理方式：

// _selfMerge：回显与本地乐观消息匹配时，仅回填真实 message_id 并返回 true
function _selfMerge(cid, raw, time, mid) {
  // 文本归一化（TGS 标签转 Unicode）后比对
  if (tn === tl && Math.abs(time - m.time) < 120) {
    m.id = mid;   // 回填真实消息 ID（供阅后即撤使用）
    return true;  // 合并成功，不重复添加
  }
}
// 兜底：身份属于 siA 或 siB 的回显，即使未匹配乐观消息也直接丢弃
var isMy = d.user_id === siA || d.user_id === siB;
if (isMy) { _selfMerge(...); return; }

九、自己消息的账号标识

为区分"当前气泡由哪个账号发出"，本地消息在插入时记录发送身份：

mh[id].push({ ..., acc: curAcc });

渲染时，若开启"自己消息显示昵称"（dnnShow），群聊中的自己消息气泡上方显示对应账号昵称（使用主题色），对方消息保持原样。_selfMerge 合并回显时保留原消息对象，仅更新 id 与 time，因此 acc 标识在合并后依然准确。

十一、已知问题与注意事项

  1. 端口冲突：两个 NapCat 实例的 WS/HTTP 端口必须错开，否则后启动的实例无法监听。
  2. 令牌独立：每个实例的 access_token 独立配置，连接时必须分别携带，不可混用。
  3. acc 参数完整性：ha() 等响应处理函数的签名必须显式声明 acc 参数（function ha(r, acc)），遗漏将引发 ReferenceError，导致列表加载中断。
  4. 群消息时序：好友列表响应存在约 1.5 秒延迟（NapCat 处理耗时），列表重发间隔需预留充足时间（本项目设为 4 秒）。
  5. 头像 URL：QQ 头像接口对 s 参数取值有要求（s=80 可能返回 400），本项目统一使用 s=100。
  6. 浏览器缓存：客户端 HTML 更新后需强制刷新（Ctrl+Shift+R），服务端已配置 no-store 响应头以降低缓存概率。
  7. 服务器进程：server-proxy 进程异常退出会导致页面无法加载，可通过检查 8098 端口监听状态确认。
  8. 同一账号重复连接：重新连接前必须重置初始化标记（_acc0Ready/_acc1Ready），否则列表加载逻辑不会重新执行。
